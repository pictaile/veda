# Навчання: лос і оптимізатор (епік E15)

Другий епік розширення на навчання. Стан: **E15 завершено** (сторі S1–S2, таски T1–T3). Autograd,
на якому це стоїть, описано в [`autograd.md`](autograd.md); операції — в [`ops.md`](ops.md).

E14 дав градієнти. Цей епік дає дві речі, які перетворюють градієнт на навчання: **число, яке варто
мінімізувати**, і **правило, як рухати параметри**.

---

## S1 — cross-entropy

**Що вимірює.** Модель заявляє ймовірність `p_t` для токена, який справді був наступним. Лос — це
здивування від цієї заяви:

```
L = −log p_t
```

| ситуація | лос |
|---|---|
| впевнено й правильно | 0 |
| впевнено й хибно | необмежено |
| рівномірна здогадка по `V` токенах | `log V` — 11.93 для Qwen3 |

Останній рядок — число, з якого стартує будь-який ненавчений запуск, і перша перевірка здорового
глузду тренувального циклу.

### Чому `log_softmax`, а не `log(softmax)`

Softmax **безпечний згори**: віднімання максимуму (E2.S3.T8) робить переповнення неможливим.
Небезпека на іншому кінці.

```
логіти [0, 200]
  softmax  ->  [0, 1]      мала ймовірність підтекла до РІВНО нуля
  log 0    ->  −inf        не число, на якому можна навчатись
```

Інформацію знищило **ділення**, і жодна наступна операція її не поверне. У лог-просторі ділення
немає:

```
log_softmax(x)_i = x_i − m − log(Σ_j exp(x_j − m))
```

Той самий максимум захищає `exp`, сума ≥ 1 → її логарифм скінченний, і `[0, 200]` дає **−200**:
великий лос, правильний і диференційовний.

### Чому backward — це віднімання

```
L = −x_t + log Σ_j exp(x_j)
dL/dx_i = p_i − [i == t]
```

Щільний якобіан softmax і обернена величина від `log` **скорочують одне одного точно**. Те саме
згортання, що в E14.S3, на крок далі — і причина, чому cross-entropy й softmax ніде не пишуть
окремо.

Як твердження про навчання: **градієнт — це помилка.** Опусти те, що передбачила модель, підніми
те, що сталося насправді, пропорційно до похибки.

**Дві властивості, які тестуються як властивості:** градієнт кожної доріжки сумується в нуль; жоден
елемент не більший за `1/lanes` за модулем — cross-entropy не може зробити велетенський градієнт із
велетенського логіта.

**Пастка із середнім.** Ділити на кількість доріжок треба **у двох місцях** — forward і backward.
Поділити лише у forward → градієнт правильної форми й у `lanes` разів завеликий.

## S2 — AdamW

Тут навчання набуває **стану**. Досі все було функцією від входів; оптимізатор пам'ятає — два
додаткові тензори на параметр, і саме тому AdamW коштує вдвічі більше за самі ваги.

```
m = β₁·m + (1−β₁)·g          перший момент: середнє градієнта
v = β₂·v + (1−β₂)·g²         другий: середнє КВАДРАТА, тобто масштаб, не напрям

m̂ = m/(1−β₁ᵗ)   v̂ = v/(1−β₂ᵗ)          корекція зсуву
θ −= lr·wd·θ                            decay, поза адаптивною машинерією
θ −= lr·m̂/(√v̂+ε)                        адаптивний крок
```

**Найкорисніший факт про Adam.** Для сталого градієнта `m/√v = g/|g| = ±1`, тож крок дорівнює
`learning_rate` **незалежно від величини градієнта**. Саме це дозволяє одному learning rate
обслуговувати мережу, шари якої мають градієнти різних порядків. У тесті це перевірено на двох
параметрах із градієнтами, що відрізняються в мільйон разів — обидва рухаються на `lr`.

**Корекція зсуву — точна, не евристика.** `m` і `v` стартують з нуля, тож після першого кроку
`m = 0.1g`, `v = 0.001g²` — це не оцінки нічого. Без корекції перший апдейт дорівнює
`0.1g/√(0.001g²) = 3.16·sign(g)` — **утричі завеликий**, саме тоді, коли модель найменш здатна це
пережити.

**Відчеплений decay — та сама «W».** Adam з L2 додає `λθ` до градієнта, тож decay потім ділиться на
`√v` разом з усім іншим. Наслідок абсурдний, щойно його побачиш: параметр із великими градієнтами
отримує **менше** регуляризації, ніж із малими. Сила регуляризації виявляється зчепленою з величиною
градієнта, чого ніхто не мав на увазі.

AdamW застосовує decay до самої ваги. Тест перевіряє це прямо: два параметри з однаковим значенням
і градієнтами, що відрізняються в пів мільйона разів, згасають **на однакову величину**.

## S2 — обрізання за глобальною нормою

Навчання стабільне, доки одна партія не виявиться не такою. Незвичний приклад, малий нормалізатор,
довга залежність — і градієнт приходить на порядок більший за звичайний. **Adam тут не рятує**: він
адаптується за `β₂ = 0.999`, тобто близько тисячі кроків, тож поодинокий сплеск проходить майже
незміненим і осідає у вагах. Один поганий крок може перекреслити години.

```
total = √(Σ по ВСІХ параметрах, ВСІХ елементах, g²)
якщо total > max_norm:   кожен g *= max_norm / total
```

**Глобально, а не потензорно.** Один множник на всі градієнти лишає їхні співвідношення недоторканими
— апдейт дивиться рівно туди ж, куди й дивився, просто не так далеко. Обрізання кожного тензора
власним порогом масштабувало б їх **різними** множниками й повернуло б крок у напрям, у який не
вказував жоден градієнт.

**Обрізання скорочує крок, а не повертає його.** Це весь задум, і причина, чому норма глобальна.

Повертається норма **до** обрізання — найінформативніше одне число у тренувальному лозі: її звичайна
величина каже, яким має бути `max_norm`; стрибок вказує на партію-винуватця; а запуск, що обрізається
щокроку, тихо перетворився на sign descent.

Місце в циклі — рівно одне:

```
loss.backward();
clip_gradient_norm(parameters, 1.0f);   // після backward: градієнти мають існувати
optimiser.step();                       // до step: далі параметри вже зрушені
optimiser.zero_grad();
```

## Віха епіку

`tests/TrainingStepTest.cpp` — перше місце, де всі частини працюють разом у порядку справжнього
циклу. Двошарова мережа на одній фіксованій партії з восьми прикладів:

```
до навчання      лос ≈ log 4 = 1.386     ненавчена модель
після 300 кроків лос < 0.01              вона запам'ятала партію
```

І тест уміє **провалитись**: той самий запуск із перевернутим знаком градієнта дає лос, вищий за
початковий. Віха, яка не може провалитись, нічого не доводить.

Цікаве спостереження з цього тесту: **обрізання жодного разу не спрацювало** при `max_norm = 1`.
Градієнт cross-entropy — це `p − one_hot`, обмежений одиницею на елемент за побудовою, тож охайний
запуск лишається під порогом. Це і є робота охоронця: він існує заради партії, яка поводиться погано,
а не заради цієї.
