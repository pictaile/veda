# Autograd (епік E14) — що реалізовано

Документ описує `veda::autograd` — перший епік розширення на навчання (Фаза 1.5). Стан: **епік E14
завершено** (сторі S1–S3, таски T1–T4; документи задач — у
`_bmad-output/planning-artifacts/roadmap/tasks/E14-*`, план — у `roadmap-training.md`).

Сусідні шари: [`ops.md`](ops.md), [`tensor.md`](tensor.md), [`harness.md`](harness.md).

**Чому це доповнення, а не переписування.** Рішення, ухвалене в E2 з інших причин: операції — чисті
функції, які **ніколи не мутують входи** (§7 архітектури). Стрічка вимагає рівно цього: вузол тримає
свої входи й може бути певен, що вони досі ті самі. Операція `add_` на місці зробила б кожен вузол
брехнею.

---

## S1 — стрічка й інструмент

**Чому зворотний режим.** Навчання потребує градієнта одного скалярного лосу за 596 млн параметрів.

```
                   проходів потрібно
прямий режим            n входів
зворотний режим         m виходів
```

У навчання `n` = 596 000 000, а `m` = **1**. Ця асиметрія — уся причина, чому зворотний режим
використовують усі.

**`check_gradient` написаний одразу**, у першій Build-тасці, а не наприкінці. Причина названа
прямо (ризик R8): **backward, помилковий у сталий множник, усе одно навчає — просто гірше**, і ніщо
в системі не поскаржиться. Тест містить навмисно зламану операцію й перевіряє, що чекер її ловить —
інструмент **доведений**, а не припущений.

### Дві семантичні речі, які витягнули тести

**`mul(x, x)` дає `2x`.** Обидва входи — один вузол, внески накопичуються. Найменший випадок, де
присвоєння замість накопичення дає правдоподібну хибну відповідь.

**Проміжні градієнти — робочий простір одного проходу.** Другий `backward()` без обнулення давав 12
замість 8: проміжні вузли зберігали градієнт і подвоювали внесок. Накопичуються лише **листки** — і
саме це робить можливим накопичення градієнтів по мікробатчах.

**Backward broadcast — це сума** по осях, які розмножувались.

## S2 — градієнти matmul, і чому AD4 зробив половину роботи наперед

```
C[i,j] = Σ_k A[i,k]·B[k,j]

dL/dA[i,k] = Σ_j G[i,j]·B[k,j]     спільний індекс останній в обох → matmul_nt(G, B)
dL/dB[k,j] = Σ_i G[i,j]·A[i,k]     → matmul(Aᵀ, G)
```

| forward | backward по A | backward по B |
|---|---|---|
| `matmul` | `matmul_nt` | `matmul(Aᵀ, G)` |
| `matmul_nt` | `matmul` | `matmul(Gᵀ, A)` |

**Дзеркало:** `_nt` у прямому проході стає звичайним matmul у зворотному, і навпаки. Найясніший
аргумент, що рішення AD4 будувати обидва варіанти було правильним.

**Помилка, яку спіймав ручний приклад:** я зайво транспонував `B` і отримав `[12, 14]` замість
`[11, 15]` — **правильну форму й неправильні числа**. Тому в тесті першим стоїть приклад, порахований
на папері, а другим — **несиметричний** випадок (`M≠K≠N`): при `M == N` хибне транспонування дає
правильну форму й проходить квадратний тест.

**Сума в градієнті ваги.** Вага `[out, in]` проти активацій `[B, T, in]` розмножена на `B·T` позицій,
тож її градієнт сумується по них. Градієнт правильної форми, але в `B·T` разів завеликий, ловиться
**лише** скінченними різницями.

**Ціна навчання:** зворотний прохід — два matmul там, де прямий був один, отже крок ≈ **три** прямі
проходи.

## S3 — нелінійності

**softmax — випадок, де наївний підхід не просто повільний, а неможливий.** Якобіан щільний:

```
dy_i/dx_j = y_i(δ_ij − y_j)
```

При `V = 151 936` це матриця на **23 мільярди** елементів на позицію. Але градієнту якобіан не
потрібен — потрібен лише його добуток із `G`:

```
dL/dx_i = y_i·(G_i − Σ_j G_j y_j)
```

Одна зважена сума на доріжку, далі поелементне віднімання й множення. **Лінійно, не квадратично** —
і та сама форма трюку зробить зрощений backward cross-entropy у E15 звичайним відніманням.

Наслідок, який перевіряється як властивість: **градієнт softmax сумується в нуль уздовж доріжки** —
виходи обмежені сумою 1, тож підняти один можна лише опустивши інші.

**rms_normalize має член зчеплення:**

```
dL/dx_i = G_i/r − x_i/(n·r³)·Σ_j G_j x_j
```

Нормалізація зв'язує доріжку: зміна одного елемента рухає вихід кожного іншого. Без другого члена
градієнт виглядає правдоподібно й навчає погано. Тест бере **неконстантну** доріжку — на константній
член зчеплення зникає, і тест пройшов би без нього.

**embedding — scatter-add, не matmul.** Прямий прохід копіює рядок `id`; зворотний додає рядок `G`
назад у градієнт таблиці. **Повторені id накопичуються** — токен, що трапився тричі, дає три внески.
До самих id не тече нічого: це індекси, диференціювати нема за чим.

## Віха епіку

Двошарова мережа навчається на іграшковій задачі, у тесті:

```cpp
h = silu(matmul_nt(x, w1));
y = matmul_nt(h, w2);
loss = sum((y − target)²);
loss.backward();
// звичайний градієнтний спуск, 60 кроків
CHECK(last_loss < first_loss * 0.05f);   // лос упав більш ніж у двадцять разів
```

Якщо бодай один градієнт епіку хибний у множник — лос падає інакше або не падає взагалі.

**Кожна операція, яку використовує прямий прохід, має перевірений градієнт.**
